# UnionBot

Установка: `npm install`. Заполните `.env` по примеру `.env.example`, затем запустите `npm start`.

Для разработки используйте `npm run dev`. Изменения исходников перезапускают бота, а сохранение статуса ивента и временные файлы тестов исключены из наблюдения в `nodemon.json`.

`SERVER_DISPLAY_NAME` в `.env` задаёт имя сервера в названии канала и префикс slash-команд. Например, `SERVER_DISPLAY_NAME="Union"` даёт `/union close`, `/union open`, `/union restart`, `/union set map`, `/union set lts`, `/union set duelyard` и `/union show maps`. Для команд пробелы по краям убираются, а имя приводится к нижнему регистру; допустимы 1–32 символа: буквы, цифры, `_` и `-`, без пробелов. Некорректное имя останавливает запуск с ошибкой настройки. При пустом значении используется `/server`. В примерах ниже указано имя `union`.

Бот проверяет игровой сервер раз в минуту; TAB также запрашивает актуальные данные. Статус `offline` появляется после трёх последовательных проверок без ответа сервера, в том числе при запуске. При единичных сбоях название канала сохраняется, а любой ответ сервера сбрасывает счётчик недоступности. Ошибки или расхождения в списке игроков не считаются отключением, если сервер ответил на запрос информации.

Discord может отложить переименование канала из-за ограничения частоты изменений. До указанного в логах срока название может отставать от данных TAB; после ожидания бот отправляет последнее актуальное название.

## Отметка ивента

В `.env` укажите ID ролей Discord, которым разрешено менять отметку:

```dotenv
EVENT_MANAGER_ROLE_IDS=123456789012345678,234567890123456789
```

Достаточно одной из указанных ролей. `/union close`, `/union open`, `/union restart`, `/union set map`, `/union set lts` и `/union set duelyard` выполняются только участниками с ролью из `EVENT_MANAGER_ROLE_IDS`. Если список пуст, все эти команды запрещены. Право администратора Discord само по себе не заменяет указанную роль. `/union show maps` доступна всем участникам Discord-сервера.
После изменения `.env` перезапустите бота.

- `/union close` отправляет новое уведомление об активности: «Изменения активности на сервере», строку «🔒 Сервер закрыт на ивент», текущий онлайн и карту в каждый канал из `CHANNEL_IDS`.
- `/union open` отправляет новое уведомление «🔓 Сервер доступен по текущему паролю» с текущим онлайном и картой в эти же каналы.

Каждый вызов команды отправляет отдельное сообщение с кнопкой TAB. Через неё можно посмотреть актуальный онлайн.
При `/union close`, `/union open` и автоматическом открытии бот запрашивает актуальные данные сервера. Если сервер не отвечает или данные не согласованы, в полях онлайна и карты будет «Нет данных», а запрошенный статус всё равно сохранится. Уведомление об открытии содержит онлайн в формате «игроков/мест» и карту.
Пока ивент активен, новые уведомления об активности содержат строку «🔒 Сервер закрыт на ивент». После `/union open` они отправляются без этой строки.
Это информационная отметка: команды не меняют доступ к игровому серверу. Подтверждение команды видит только её автор.

Во время ивента название каналов имеет вид `🔒・union・2⁄26・карта`. При ручном или автоматическом открытии замок сменяется обычным индикатором онлайна. Счётчик игроков и карта продолжают обновляться во время ивента.

Команда с именем из `SERVER_DISPLAY_NAME` регистрируется при запуске в Discord-серверах настроенных каналов. После успешной регистрации бот удаляет прежние slash-команды `/server` и `/event`, если их имя отличается от настроенного; остальные команды сохраняются.
Для отправки уведомлений боту нужен доступ к каналу, отправке сообщений и встраиванию ссылок (Embed Links).

Состояние ивента хранится в `event-status.json` рядом с `index.ts` в корне проекта и восстанавливается после перезапуска. Сохраните этот файл при переносе бота. Статус общий для одного игрового сервера во всех настроенных каналах.

Через четыре часа после `/union close` бот автоматически снимает статус ивента и отправляет обычное объявление об открытии сервера. Ручной `/union open` отменяет таймер, а повторный `/union close` начинает новый отсчёт на четыре часа. Срок сохраняется при перезапуске; если он истёк, пока бот был выключен, объявление отправится после подключения к Discord. Для активного ивента, сохранённого старой версией без срока, первый отсчёт начнётся после запуска обновлённого бота.

## Перезапуск сервера Nitrado

`/union restart` перезапускает игровой сервер Chivalry 2 через [официальный API Nitrado](https://doc.nitrado.net/). Доступ разрешён тем же ролям из `EVENT_MANAGER_ROLE_IDS`, что и для `/union close` и `/union open`. Если список ролей пуст, перезапуск запрещён.

В `.env` добавьте:

```dotenv
NITRADO_API_TOKEN=your_nitrado_token
NITRADO_SERVICE_ID=12345678
```

Нужен токен Nitrado с доступом к нужной услуге и правом `ROLE_WEBINTERFACE_GENERAL_CONTROL`. Для постоянной работы можно использовать long-life token; токен храните только в `.env`. `NITRADO_SERVICE_ID` — числовой ID услуги (`service_id`), а не ID пользователя, IP-адрес или порт. Его можно получить из списка услуг `GET https://api.nitrado.net/services` или параметра `service_id` в ссылке веб-интерфейса Nitrado. Проверьте, что выбрана нужная услуга. Без токена или корректного ID команда сообщает, что перезапуск не настроен; остальные функции бота продолжают работать.

После изменения `.env` перезапустите бота: он зарегистрирует подкоманду `restart` для имени из `SERVER_DISPLAY_NAME` (в примере `/union restart`).

- Бот запрашивает текущий онлайн. Если игроков нет, запрос на перезапуск отправляется сразу.
- Если есть игроки, бот показывает их количество и спрашивает подтверждение кнопками «Перезапустить» и «Отмена». При недоступном или несогласованном онлайне подтверждение тоже обязательно.
- Подтверждение видно только автору команды, действует 60 секунд и может быть использовано только им. Если роль сняли до подтверждения, рестарт отменяется. При отмене или истечении времени запрос Nitrado не отправляется.
- Пока ожидается подтверждение или проверяется запуск, повторные команды блокируются во всех каналах. После завершения обработки команды новый перезапуск доступен сразу, если Nitrado не сообщает о выполняющейся операции.
- Бот проверяет статус Nitrado примерно раз в пять секунд в течение пяти минут. Сообщение о завершении появляется после перехода через остановку/перезапуск в `started`; если переход не удалось увидеть или API недоступен, бот просит проверить панель хостинга. Это подтверждение запуска по данным Nitrado; игровой онлайн и карта продолжают обновляться обычным мониторингом.

Бот проверяет состояние Nitrado до запроса и повторно после подтверждения, чтобы не дублировать операцию, начатую через панель хостинга. В журнал Nitrado передаются ID автора и Discord-сервера. При таймауте или ошибке запрос на рестарт автоматически не повторяется: хостинг мог уже принять его. Статус ивента при перезапуске не меняется.

## Смена карты с перезапуском

`/union set map` сохраняет выбранные карты в поле **Map rotation** панели Nitrado и затем перезапускает сервер. После выбора этой подкоманды заполните обязательный параметр `maps`: одну карту (`FFA_Duelyard`) или несколько полных названий через пробел. Пример команды с несколькими картами:

```text
/union set map TO_Coxwell TO_Lionspire TO_RudhelmSiege
```

Бот сохраняет каждую карту отдельной строкой в указанном порядке. Повторы сохраняются: `TO_Falmire TO_DarkForest TO_Falmire` задаёт три позиции ротации, где первая и третья карта одинаковые. Лишние пробелы между названиями допускаются. Длина параметра `maps` — до 1000 символов.

`/union set lts` — отдельная подкоманда без аргументов. Она устанавливает все известные карты с префиксом `LTS_` в порядке списка: `LTS_Wardenglade`, `LTS_TournamentGrounds`, `LTS_FightingPit`, `LTS_Courtyard`, `LTS_Galencourt`, `LTS_Falmire`. Бот целиком заменяет прежнюю ротацию этими шестью картами, проверяет сохранение и перезапускает сервер. Имя подкоманды пишется строчными буквами по правилам Discord.

`/union set duelyard` — отдельная подкоманда без аргументов. Она заменяет всю ротацию одной строкой `FFA_Duelyard`, проверяет сохранение и перезапускает сервер. Остальные карты и повторные записи Duelyard удаляются. Если ротация уже состоит ровно из одной `FFA_Duelyard`, команда отклоняется без сохранения и перезапуска.

В `/union set map` принимаются только полные названия с режимом из списка в [`src/server-maps.ts`](src/server-maps.ts), например `FFA_Duelyard`, `TO_Coxwell` или `PR_LTS_Raid`. Название и регистр должны совпадать со списком. Если хотя бы одна карта неизвестна, вся команда отклоняется до обращения к Nitrado; настройка и перезапуск не выполняются.

`/union show maps` показывает все 44 доступные карты с группировкой по режимам. Ответ виден только автору команды, как список игроков по кнопке TAB. Просмотр доступен всем участникам Discord-сервера: роль управления и настроенный Nitrado не нужны.

В `/union set map` названия карт вводятся вручную в параметре `maps`. Полные названия можно скопировать из ответа `/union show maps`.

Команда целиком заменяет прежнюю ротацию переданным списком. Если указана одна карта, остаётся только она. Это соответствует изменению поля Map rotation, нажатию «Сохранить» и затем перезапуску; [инструкция Nitrado](https://server.nitrado.net/en-GB/guides/chivalry-2-map-rotation-server-guide) описывает тот же порядок. Кроме `ROLE_WEBINTERFACE_GENERAL_CONTROL`, токену нужны права `ROLE_WEBINTERFACE_SETTINGS_WRITE` для сохранения и `ROLE_WEBINTERFACE_SETTINGS_READ` для проверки сохранённого значения ([API настроек Nitrado](https://doc.nitrado.net/#api-Gameserver-UpdateSetting)).

Перед запросом подтверждения и ещё раз непосредственно перед сохранением бот читает текущую ротацию из настроек Nitrado. Если все карты, их порядок и количество повторов совпадают, команда отклоняется с сообщением, что карта или ротация уже установлена. Сохранение и перезапуск не отправляются. `/union set lts` сравнивает текущую ротацию с полным списком карт LTS. Пробелы вокруг строк, пустые строки и формат переноса строк не влияют на сравнение; изменение порядка или повторов считается новой ротацией. Если текущие настройки не удалось прочитать, смена ротации отменяется. Для обычного перезапуска с прежними настройками доступна `/union restart`.

Бот сначала проверяет онлайн и при необходимости просит подтверждение с полной ротацией в выбранном порядке. До подтверждения настройки не меняются. После сохранения бот перечитывает `config.map-rotation` через API и отправляет один перезапуск только при совпадении всех карт, их порядка и повторов. Если сохранение не удалось подтвердить, перезапуск не отправляется; ротация могла сохраниться, поэтому бот просит проверить панель Nitrado. Если ошибка возникла после подтверждённого сохранения, ответ отдельно сообщает, что ротация уже сохранена. Запросы сохранения и перезапуска автоматически не повторяются.

Права Discord, ожидание запуска и блокировка одновременных операций общие с `/union restart`. После обновления исходников перезапустите бота, чтобы зарегистрировалась группа `set` с отдельными подкомандами `map`, `lts` и `duelyard`. Сообщение о сохранённой ротации и запуске подтверждает настройку в панели и состояние Nitrado; фактическая игровая карта обновляется обычным мониторингом сервера.

Проверки: `npm test` и `npm run typecheck`. Тесты перезапуска и смены карты используют подмену API и не обращаются к реальному серверу.
