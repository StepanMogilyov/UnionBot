# UnionBot

Установка: `npm install`. Заполните `.env` по примеру `.env.example`, затем запустите `npm start`.

Для разработки используйте `npm run dev`. Изменения исходников перезапускают бота, а сохранение статуса ивента и временные файлы тестов исключены из наблюдения в `nodemon.json`.

## Отметка ивента

В `.env` укажите ID ролей Discord, которым разрешено менять отметку:

```dotenv
EVENT_MANAGER_ROLE_IDS=123456789012345678,234567890123456789
```

Достаточно одной из указанных ролей. Если список пуст, команды не меняют статус.
После изменения `.env` перезапустите бота.

- `/event start` отправляет новое уведомление об активности: «Изменения активности на сервере», строку «🔒 Сервер закрыт на ивент», текущий онлайн и карту в каждый канал из `CHANNEL_IDS`.
- `/event stop` отправляет короткое новое уведомление «🔓 Сервер открыт» в эти же каналы, без онлайна и карты.

Каждый вызов команды отправляет отдельное сообщение с кнопкой TAB. Через неё можно посмотреть актуальный онлайн.
При `/event start` бот запрашивает актуальные данные сервера. Если сервер не отвечает или данные не согласованы, в полях онлайна и карты будет «Нет данных», а статус закрытия всё равно сохранится. `/event stop` не требует запроса игрового сервера.
Пока ивент активен, новые уведомления об активности содержат строку «🔒 Сервер закрыт на ивент». После `/event stop` они отправляются без этой строки.
Это информационная отметка: команды не меняют доступ к игровому серверу. Подтверждение команды видит только её автор.

Команда `/event` регистрируется при запуске в Discord-серверах настроенных каналов.
Для отправки уведомлений боту нужен доступ к каналу, отправке сообщений и встраиванию ссылок (Embed Links).

Состояние ивента хранится в `event-status.json` рядом с кодом и восстанавливается после перезапуска. Сохраните этот файл при переносе бота. Статус общий для одного игрового сервера во всех настроенных каналах.

Проверки: `npm test` и `npm run typecheck`.
